# F05: current recipient reads

The first commit records five failing read regressions. The fix shares one current recipient authorization and integrity guard across the deliveries API, dashboard service, insights and outgoing evidence webhooks. It checks the exact active grant and recipient, current identity/terms, current routing authority, snapshot fingerprint, access scope and issued credential version/signature. Controller audit reads retain their immutable records. A correction or withdrawal also removes old share packages from recipient replay and sharing-page reads, and prevents new shares from using obsolete controller receipts. Independent explicit share grants retain their own approval lifecycle.

Validation: build, 132 unit/backend tests in 32 files, 40 Worker/rendered/redirect checks, focused lint and whitespace PASS. Tests revoke the grant, recipient identity, terms version, routing authorization and underlying credential independently; each protected recipient read loses its payload while the controller audit and database rows remain. Existing webhook tests also cover corruption and tampering. All fixtures are synthetic in disposable D1; providers are intercepted. Published trees match tested commits.

This PR does not claim downstream invalidation is complete: the agreed vle-evidence/1 metadata tombstones and consumer eviction depend on the separately ordered mint step 4 contract repair. VLE's current proof receiver does not retain result snapshots and remains OFF. Historical downloaded copies cannot be recalled. No live result, account, notification, production data or migration was used. Draft PR only, no merge or deploy.
